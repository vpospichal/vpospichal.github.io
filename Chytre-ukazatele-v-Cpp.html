Chytré ukazatele v C++ a správa paměti

Tento dokument shrnuje problematiku správy paměti v moderním C++, srovnání chytrých ukazatelů s jinými přístupy a specifika fungování typu std::string.

1. Proč používat chytré ukazatele?

Chytré ukazatele (smart pointers) automaticky řídí životní cyklus dynamické paměti na principu RAII (Resource Acquisition Is Initialization). Paměť je automaticky uvolněna v destruktoru, jakmile ukazatel opustí svůj rozsah platnosti (scope).

Srovnání různých přístupů ke správě paměti

Správa paměti Zcela manuální Plně automatická Automatická přes vlastnictví
Riziko úniku paměti Vysoké (opomenutí uvolnění) Téměř nulové Minimální
Dopad na výkon Žádný (nulová režie) Vysoký (pauzy kvůli GC) Nulový až minimální

2. Typy chytrých ukazatelů v C++

A) std::unique_ptr (Výhradní vlastnictví)

Dynamický objekt vlastní pouze jedno místo v kódu. Ukazatel nelze zkopírovat, lze jej pouze přesunout pomocí std::move. Má nulovou režii oproti surovému ukazateli.

#include <memory>
#include <iostream>

void uniqueExample() {
    // Vytvoření unique_ptr (od C++14)
    std::unique_ptr<int> ptr1 = std::make_unique<int>(10);
    
    // std::unique_ptr<int> ptr2 = ptr1; // CHYBA: Kopírování je zakázáno!
    std::unique_ptr<int> ptr2 = std::move(ptr1); // Správně: Přesun vlastnictví
} // Zde ptr2 zaniká a paměť se automaticky uvolní

B) std::shared_ptr (Sdílené vlastnictví)

Na objekt může odkazovat více částí programu současně. Ukazatel interně počítá reference (vlastníky). Paměť se uvolní, až když zanikne poslední shared_ptr mířící na daný objekt.

void sharedExample() {
    std::shared_ptr<int> ptr1 = std::make_shared<int>(42);
    {
        std::shared_ptr<int> ptr2 = ptr1; // Počet vlastníků = 2
        std::cout << ptr1.use_count(); // Vypíše 2
    } // ptr2 zaniká, počet vlastníků klesá na 1. Paměť stále drží.
} // ptr1 zaniká, počet vlastníků = 0 -> paměť se maže

C) std::weak_ptr (Nedestruktivní odkaz)

Slouží jako doplněk k shared_ptr. Nezvyšuje počítadlo referencí, čímž brání vzniku cyklických závislostí (paměťových úniků). Pro přístup k datům je nutné jej dočasně zamknout metodou lock().

3. Jak spravuje paměť typ std::string?

Standardní řetězec std::string uvnitř sebe nepoužívá chytré ukazatele typu unique_ptr nebo shared_ptr. Spoléhá na přímou nízkoúrovňovou správu optimalizovanou na výkon.

Hlavní důvody tohoto návrhu:

  • SSO (Small String Optimization): Pokud je řetězec krátký (cca do 15–23 znaků), uloží se do fixního pole přímo na zásobníku (stacku). K žádné alokaci na haldě (heapu) nedochází.
  • Sémantika hodnoty: String se chová jako běžné číslo. Při přiřazení (a = b) se vytvoří nezávislá kopie celého textu. shared_ptr by způsobil nechtěné sdílení modifikací.

Rozdíly v uložení dat

Typ objektu Umístění dat v paměti Chování při kopírování
std::string (krátký) Na zásobníku (stack) uvnitř objektu Znaky se rychle zkopírují v rámci zásobníku.
std::string (dlouhý) Na haldě (heap) Alokuje se nová paměť na haldě a text se překlopí.
std::shared_ptr<std::string> Vždy na haldě (heap) Text se nekopíruje, pouze se zvýší počítadlo referencí.
